 需求

 Work Item List 應⽤程式開發

 開發⼀個 **Web 應⽤程式**，其⽬的是允許 **前台使⽤者查看並操作 Work Item 列表（勾選、確

 認、查看詳情）**。每位使⽤者登入後，都能看到管理者所新增的 Work Item 列表，並針對每個項⽬

 進⾏ **個⼈化的勾選與確認操作**。換⾔之，勾選狀態僅針對該使⽤者本⼈保存，其他使⽤者登入時，

 仍會看到屬於⾃⼰尚未勾選的狀態，並能獨立操作。當使⽤者重新訪問時，系統需保持該使⽤者先前的

 勾選與確認狀態。

 這個開發題圍繞⼀個名為 "Work Item List" 的網⾴介⾯展開，前台使⽤者可以瀏覽並與列表互動，

 對 Work Item 進⾏勾選，並在按下 "Confirm" (或類似按鈕) 後，系統保存該使⽤者的操作紀錄。使

 ⽤者可以關閉網⾴後再登入，仍能看到⾃⼰之前的操作狀態。此外，使⽤者可點擊 Work Item 查看詳

 細資料。

 後台則需要提供介⾯或 API，允許管理者新增、修改和刪除列表中的 Work Item。此專案的重點在於開

 發⼀個具有基本 CRUD (新增、讀取、更新、刪除) 功能的 Web 應⽤程式，並⽀援前台使⽤者的個⼈化

 互動需求。應徵者需要同時考慮前台的呈現與使⽤者操作流程，以及後台資料的管理與持久化。

 User Stories

 前台使⽤者

 1. 查看 Work Item 列表

 作為前台使⽤者，我想要在網⾴上查看 Work Item 列表，以便了解有哪些待辦項⽬。

 ●

 列表呈現  ：

 ○

 ○

 「標題」、「狀態」欄位。

 ●

 作為前台使⽤者，我想要勾選⼀或多個 Work Item 並按下「確認」以標記為已確認，或在
 需要時將其狀態改回待確認，以便正確記錄和調整我的操作。

 ●

 多選功能  ：

 ○
 ○
 ○

 每列 Work Item 左側必須有⼀個勾選⽅塊（checkbox）。
 點擊任⼀勾選⽅塊後，該列背景或文字要顯⽰已選中狀態。
 表頭提供「全選」⽅塊，勾選後⼀次選中／取消選中所有顯⽰中的項⽬。

 ●

 確認操作  ：

 ○
 ○

 ○

 當⾄少有⼀個勾選⽅塊被勾選時，「確認」按鈕才可點擊；否則為 disabled。
 點擊「確認」後，發送 API 請求，將我所勾選的項⽬狀態更新為「已確認」（僅
 針對我個⼈的紀錄）。
 更新完成後，清除所有勾選，並在表格上顯⽰對應列的「狀態」欄位變更為「已確
 認」。

 ●

 撤銷操作  ：

 ○

 在列表中，僅對狀態為「已確認」的項⽬，顯⽰「撤銷確認」按鈕（或「標記為待
 確認」連結）。

 ○

 ○
 ○

 ○

 點擊「撤銷確認」後，跳出確認對話框：「確定要將此項⽬標記回『待確認』

 按「確定」後，發送 API 請求將該項⽬的狀態（僅針對我本⼈）更新為「待確
 認」。
 更新成功後，該列「狀態」欄位顯⽰「待確認」，並隱藏「撤銷確認」按鈕。

 ●

 使⽤者反饋  ：

 ○

 ○

 更新成功後，顯⽰提⽰訊息（例如「已成功確認 X 項⽬」或「已將 X 項⽬標記為
 待確認」）。
 若更新失敗，顯⽰錯誤訊息並保留原狀態。
